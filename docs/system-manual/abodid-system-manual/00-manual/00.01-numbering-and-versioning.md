Status: Current

## 1. Numbering Architecture

The Abodid System Manual enforces an immutable, two-level fixed numeric chapter taxonomy from Chapter 00 to Chapter 10.

Subsections extend hierarchically using dot notation and may expand indefinitely without modifying parent chapter numbers or shifting adjacent topics.

```text
Chapter Key (Fixed 00–10)
  └── Section (e.g., 03.04)
        └── Subsection (e.g., 03.04.01)
              └── Sub-subsection (e.g., 03.04.01.02)
```

## 2. Invariant Rules of Numbering

1. **Never Renumber Top-Level Chapters**: A new top-level chapter cannot be introduced outside the 00–10 range. Emerging topics belong in subsections or in Chapter 07 (Reserved / Field Notes).
2. **Never Renumber on Insertion**: When inserting a new topic between existing sections, add a new nested identifier (e.g., between 03.04 and 03.05, insert 03.04.01 or create an appended leaf). Existing section links must remain unbroken.
3. **Leading Zeros Required**: All single-digit chapters and major sections require a leading zero (`00` through `09`).

## 3. Versioning Strategy

The manual follows Semantic Versioning (SemVer `MAJOR.MINOR.PATCH`):

- **MAJOR (`X.0.0`)**: Comprehensive structural overhaul of the ecosystem (e.g., complete framework migration, foundational database architecture replacement).
- **MINOR (`1.X.0`)**: Addition of a new subsystem, new research project suite, new subdomain, or major feature release.
- **PATCH (`1.0.X`)**: Clarifications, technical errata, updated API parameter specifications, or bug postmortems.

All version increments must be logged in [CHANGELOG.md](../CHANGELOG.md) with corresponding commit references.
