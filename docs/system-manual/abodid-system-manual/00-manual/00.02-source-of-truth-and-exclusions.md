# 00.02 — Source of Truth and Exclusion Principles

Status: Current  
Last Updated: 2026-09-18  

---

## 1. Primary Source of Truth

The current working Git repository (`/personal-site`) is the ultimate source of truth for all documentation.

Where differences arise between external documentation, past design mocks, and the active codebase:
1. The **active codebase, current database migrations, and production configuration files** represent the true reality.
2. Older commits and historical branches are referenced selectively only when they illuminate the rationale behind a non-obvious design or architectural decision.

### 1.1. Selective Commit Archaeology

Historical investigations focus on commits with the following markers:
- `revamp`, `complete revamp`, `redesign`
- `restructure`, `migration`, `refactor`
- `major update`, `schema update`

Arbitrary historical recreation and exhaustive change replay are explicitly avoided to maintain concise, relevant documentation.

---

## 2. Status Classification Tags

To prevent ambiguity, every document, subsystem, or architectural description must declare its implementation status:

| Tag | Meaning |
| :--- | :--- |
| `Status: Current` | Verified active in production code and actively maintained. |
| `Status: Historical` | Previously existed in earlier iterations; preserved for context or postmortem analysis. |
| `Status: Experimental` | Code exists in repo/Lab, actively tested, but not committed to permanent production APIs. |
| `Status: Planned` | Architecturally designed or scheduled, but not yet implemented in code. |
| `Status: Unverified` | Code exists but runtime state, external dependency, or credentials could not be fully audited. |

> **Crucial Invariant**: Never present planned functionality as if it already exists.

---

## 3. Strict Exclusions and Sanitization

### 3.1. Zero Secrets Policy
Under no circumstances may any secret, credential, private key, or password be placed in the manual:
- **Forbidden**: Live Supabase Service Role keys, OpenRouter API keys, Resend tokens, AWS/R2 secret keys, database connection strings containing passwords, private encryption salts.
- **Permitted**: Environment variable keys (e.g., `OPENROUTER_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY`), schema structures, and public publishable keys (`PUBLIC_SUPABASE_ANON_KEY`).

### 3.2. Exclusion of Media Bloat
- No screenshot archives or bulk image dumps.
- Diagrams are rendered strictly as text-based **Mermaid** blocks within Markdown files.
- UI screenshots are permitted only when demonstrating an intricate visual interaction or design token behavior that text cannot unambiguously convey.
