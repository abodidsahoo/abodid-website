Status: Current  
Last Updated: 2026-09-18

## 1. Vendor Dependency and Portability Matrix

The ecosystem deliberately minimizes proprietary vendor lock-in by using standardized open-source primitives. If any primary vendor changes terms, pricing, or availability, drop-in alternatives are documented below:

| Current Layer / Service | Current Role | Viable Modern Alternatives | Migration Complexity | Portability Strategy |
| :--- | :--- | :--- | :--- | :--- |
| **Astro 5.x** | Core SSG / SSR Framework | Next.js, Remix, Vite + Fastify | Low–Medium | Content is pure Markdown/Postgres blocks; UI components use standard React/HTML. |
| **Vercel** | Edge CDN & Serverless Compute | Cloudflare Pages, Fly.io, Netlify, AWS ECS | Low | Astro builds standard static HTML + Node serverless handler. Switch adapter in `astro.config.mjs`. |
| **Supabase** | Hosted Postgres, Auth & Vectors | Self-hosted Postgres + pgvector, Neon, Crunchy Data | Low | Standard SQL schemas in `supabase/migrations/`; no proprietary database features. |
| **Cloudflare R2** | Media Object Storage | AWS S3, Backblaze B2, MinIO, Wasabi | Very Low | Uses standard AWS S3 SDK (`@aws-sdk/client-s3`); change endpoint and credentials. |
| **OpenRouter** | Multi-Model LLM Gateway | Direct Anthropic / OpenAI / Gemini APIs, Groq, Ollama | Very Low | Standard OpenAI-compatible REST format. |
| **Resend** | Transactional SMTP & Emails | Postmark, AWS SES, SendGrid | Very Low | Decoupled email templates in React Email (`@react-email/components`). |

---

## 2. Vendor Lock-In Mitigation Principles

1. **Standardized Protocols**: S3-compliant storage APIs, OpenAI-compliant inference schemas, and standard PostgreSQL SQL migrations.
2. **Framework Decoupling**: Business logic resides in pure TypeScript modules (`src/lib/`) rather than framework-specific request hooks.
3. **Data Sovereignty**: The core knowledge base (Obsidian vault) exists as plain-text Markdown files on the local filesystem.
