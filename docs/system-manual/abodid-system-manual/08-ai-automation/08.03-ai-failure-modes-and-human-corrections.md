# 08.03 — AI Failure Modes, Hallucination Postmortems, and Lessons

Status: Current / Postmortem  
Last Updated: 2026-09-18

## 1. The Human-in-the-Loop Philosophy

AI tools accelerate development only when strictly constrained by human taste and rigorous verification. This document captures real-world failure modes where unguided AI assumptions broke system functionality, and the permanent architectural fixes implemented as a result.

---

## 2. Postmortems: AI Assumptions vs Human Corrections

### 2.1. Case 1: The Readiness Ping Race Condition
- **AI Assumption**: Before executing vector similarity RPC in `/api/vault-chat`, an LLM agent added a separate database `SELECT 1` readiness ping to "ensure database health."
- **Problem Caused**: Doubled database round-trip latency on every user query and triggered intermittent connection pool timeouts on high-concurrency requests.
- **Human Correction**: Removed the readiness ping entirely; the vector RPC call already fails gracefully into a top-level try/catch block.
- **Better Prompt / Constraint**: "Do not introduce preemptive connectivity health checks before calling resilient database RPCs."
- **Permanent Lesson**: Extra round-trips masquerading as defensive programming add latency and fail points without adding signal.

### 2.2. Case 2: Hallucinated Markdown Citations
- **AI Assumption**: In the Vault Chat RAG pipeline, the model was instructed in plain English to "cite your sources with [1], [2]."
- **Problem Caused**: The model hallucinated non-existent source indices (e.g., citing `[7]` when only 3 source chunks were retrieved), creating broken UI link pills.
- **Human Correction**: Implemented `remapVisibleCitations()` in JavaScript to programmatically parse, validate, and remap citations strictly against the retrieved chunk array.
- **Better Prompt / Constraint**: Combine numeric citation instructions with deterministic post-processing validation.
- **Permanent Lesson**: Never allow raw generative LLM output to directly control critical UI navigation identifiers without deterministic verification.

### 2.3. Case 3: Accidental Private Note Leakage
- **AI Assumption**: An automated script ingested all `.md` files found in the vault root directory, assuming all files were public.
- **Problem Caused**: Private journal notes and administrative contact lists were indexed into vector storage.
- **Human Correction**: Created `detectSensitiveVaultContent()` regex scanner and explicit path filtering (`OBSIDIAN_VAULT_INDEX_PATHS` vs `OBSIDIAN_VAULT_EXCLUDE_PATHS`), forcing sensitive notes to `is_public = false`.
- **Better Prompt / Constraint**: Enforce default-deny privacy filters ahead of vector embedding.
- **Permanent Lesson**: Ingestion pipelines must operate on explicit opt-in whitelists, backed by automated heuristic sensitivity scanners.
